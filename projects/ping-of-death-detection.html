Detecting a Ping of Death with Snort and Telegram Alerts

I generated oversized ICMP traffic in a contained lab, wrote a custom Snort signature to catch it, and connected the IDS to a Telegram bot so an alert reaches my phone within seconds.

SummaryA Ping of Death sends ICMP packets far larger than normal to crash or freeze a host. I built the full detection pipeline: traffic generation → signature detection → live log monitoring → instant mobile alert.

Why this matters

Modern operating systems are patched against the original Ping of Death, but oversized and malformed ICMP traffic is still a common sign of reconnaissance, misconfiguration or denial-of-service attempts. A SOC analyst needs to see it quickly. This lab focuses on how quickly an alert can go from the wire to a human.

1. Writing the detection rule

Normal ping payloads are small (56–64 bytes by default). I wrote a signature that fires on any ICMP packet with a payload over 1,400 bytes, which is close to the size of a standard Ethernet frame and far above legitimate ping traffic:

alert icmp any any -> any any (
    msg:"ICMP Ping of Death Detected";
    dsize:>1400;
    sid:1000001; rev:1;
)

The rule lives in local.rules, which is included from snort.conf. Snort then runs in console-alert mode on the interface being watched.

2. Validating with test traffic

To prove the rule works, I sent oversized ICMP packets to localhost only, so no other machine was affected. Snort raised the alert straight away. I also captured the same traffic in Wireshark to confirm the payload size and the IP fragmentation pattern that oversized pings produce.

3. Real-time alerting to Telegram

A detection that nobody sees isn't much use. I wrote a small Bash helper that posts a message through the Telegram Bot API, then piped Snort's alert log into it:

# telegram_alert.sh: send a message to the analyst's chat
TOKEN="<BOT_TOKEN>"
CHAT_ID="<CHAT_ID>"
curl -s -X POST "https://api.telegram.org/bot$TOKEN/sendMessage" \
     -d chat_id="$CHAT_ID" -d text="$1"

# watch the IDS log and forward matching alerts
tail -Fn0 /var/log/snort/alert | while read line; do
  echo "$line" | grep -q "Ping of Death" && ./telegram_alert.sh "$line"
done

Techniques practised

Signature-based detection

Writing and tuning a Snort rule around a specific, measurable property (payload size).

Anomaly reasoning

Choosing a threshold that separates normal ping traffic from abuse.

Packet analysis

Checking the attack in Wireshark rather than trusting the alert alone.

Log monitoring & response

Turning a log line into an actionable notification for incident response.

What I learned

  • A threshold rule is simple but needs justification. I can explain why I chose 1,400 bytes and what could cause false positives (for example, legitimate path-MTU testing).
  • Detection and notification are separate problems, and the second one is often where real SOCs lose time.
  • Keeping test traffic on loopback is a good habit: you prove the control works without putting anything else at risk.

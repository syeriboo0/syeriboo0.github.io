Network Security Lab Series: Packets, TCP Flags and Email Protocols

A series of hands-on labs: crafting custom packets, fingerprinting hosts by how they answer different TCP flag combinations, and analysing what email and HTTPS traffic reveals on the wire.

SummaryFour labs that built my packet-level understanding. I sent ICMP/UDP/TCP packets with custom payloads, compared eight Nmap scan types against one host, and captured SMTP, POP3, IMAP and HTTPS sessions to see which protocols expose data in the clear.

Lab 1: Crafting custom packets

I wrote a Python program that sends a custom payload ("Hello, this is a try!") over ICMP, UDP and TCP, then repeated the test from the command line with Nping against the default gateway:

nping --icmp --data-string "hello everyone" <gateway>
nping --udp  --data-string "hello everyone" <gateway>
nping --tcp  --data-string "hello everyone" <gateway>

Capturing these in Wireshark showed exactly where the payload sits in each protocol's packet structure.

Lab 3: TCP flag behaviour and host fingerprinting

I scanned the same host with eight Nmap techniques and recorded how it answered each flag combination:

ScanFlags sentResponseInterpretation
TCP Connect (-sT)SYN → SYN-ACK → ACKNo responseLikely filtered by firewall/ACL
SYN (-sS)SYNRSTPort closed
FIN (-sF)FINRSTClosed (RFC 793 behaviour)
NULL (-sN)noneRSTClosed (RFC 793 behaviour)
Xmas (-sX)FIN, PSH, URGRSTClosed (RFC 793 behaviour)
ACK (-sA)ACKRSTUnfiltered
Window (-sW)ACK + window checkNo responseFiltered or unsupported
Maimon (-sM)FIN, ACKRSTClosed

Findings

  • No reply to the Connect and Window scans points to filtering.
  • The same RST reply to FIN, NULL and Xmas scans shows RFC-compliant TCP behaviour, which helps fingerprint the target OS.
  • The ACK scan is the clearest way to check filtering without probing service state.
  • FIN, NULL and Xmas scans can slip past basic firewalls that only block SYN packets. That's why defenders should use stateful inspection.

Labs 4 & 5: Email and TLS traffic analysis

  • Sent email with Python over SMTP and read it back over POP3 using a Mailtrap sandbox inbox.
  • Used OpenSSL (s_client) to open TLS connections to HTTPS sites and to mail servers. I captured each handshake in Wireshark and compared what is visible before and after encryption.
  • Captured SMTP and IMAP sessions for both Mailtrap and Gmail, then tried to decode the email in Wireshark. Unencrypted sessions gave up their content; TLS-protected sessions did not.

What I learned

  • I can read a TCP conversation flag by flag and explain what each response says about the target.
  • Scan choice is a trade-off between stealth, speed and the information you get back.
  • TLS changes what a network observer can see, and Wireshark makes that difference easy to show to non-technical people.

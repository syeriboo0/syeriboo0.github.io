Credential Harvesting Detection over SMTP

I built an isolated two-machine lab where credentials are sent over an unencrypted SMTP session, then detected the exposure with Snort and Wireshark and sent alerts to Telegram.

SummarySMTP AUTH LOGIN only Base64-encodes the username and password. That's encoding, not encryption, so anyone on the network path can read them. I set up a lab to show this risk and built detection that flags it.

Lab architecture

Windows XP (client)

Opens a plain Telnet session to a sandbox SMTP server (Mailtrap) and authenticates with AUTH LOGIN. This simulates a user or legacy app sending credentials in clear text.

Kali Linux (sensor)

Runs Snort as the IDS on the VMware host-only interface and Wireshark for packet analysis. A Python script forwards alerts to Telegram.

Everything ran on an isolated VMware host-only network against a sandbox mail service. No real accounts or third-party systems were involved.

1. Detection rules

I wrote content-matching rules that flag SMTP authentication attempts on both the standard port and the sandbox port:

alert tcp any any -> any 2525 (msg:"SMTP AUTH LOGIN attempt";
      content:"AUTH LOGIN"; sid:1000001; rev:1;)
alert tcp any any -> any 25   (msg:"SMTP AUTH LOGIN attempt on port 25";
      content:"AUTH LOGIN"; sid:1000002; rev:1;)

2. Packet analysis in Wireshark

I used these display filters to isolate the session:

tcp.port == 2525 || tcp.port == 25
tcp contains "AUTH LOGIN"

Following the TCP stream showed the full SMTP conversation: EHLO, AUTH LOGIN, then two Base64 strings. Decoding those strings gives back the plaintext username and password, which proves that an attacker sniffing the network could harvest them.

3. Alerting

A short Python script using requests posts to the Telegram Bot API whenever the IDS reports the pattern, so the analyst is notified straight away.

import requests

def send_alert(msg):
    url = f"https://api.telegram.org/bot{BOT_TOKEN}/sendMessage"
    requests.post(url, data={"chat_id": CHAT_ID, "text": msg})

send_alert("IDS Alert: SMTP credential exposure detected")

Recommendations

  • Enforce SMTP over TLS (STARTTLS on 587 or implicit TLS on 465) and reject plaintext AUTH on port 25.
  • Retire legacy clients that can't do encrypted authentication.
  • Keep IDS signatures for cleartext authentication as a detective control, because they catch misconfigured devices as well as attackers.

What I learned

  • Encoding is not encryption. Base64 credentials are as exposed as plaintext.
  • Wireshark's "Follow TCP Stream" quickly turns raw packets into evidence you can show someone.
  • I got a feel for how a sensor's placement (which interface it watches) decides what it can see.
